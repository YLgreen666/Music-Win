## 仍需在目标浏览器执行的实机验收

1. Windows Chrome / Edge 分别使用原生“选择音乐文件”“导入音乐文件夹”：授权嵌套目录、关闭浏览器重开、撤回权限后点击恢复、移动文件后重新关联。代码与替身测试已覆盖，内置浏览器不能完整控制系统级权限弹窗。
2. 导入自己的 MP3、FLAC、M4A/AAC、OGG 等编码样本，确认该浏览器实际解码能力；当前真实解码证据为合成 WAV。可播放格式以浏览器为准。
3. 长时间后台播放、系统 Media Session 控件、睡眠唤醒、PWA 安装后的独立窗口，以及拔除外置磁盘的权限/文件恢复。
4. 在目标 GPU 上检查千首真实封面库的渲染/导入性能、强制禁用 WebGL 的列表降级与磁盘配额不足。千首映射和视口裁剪实现已覆盖，未声称完成这些硬件压力测试。

未在 GitHub 发布、推送或部署。桌面安装包与第三方平台登录/接口留在后续阶段。

## 关闭标签修订

用户报告关闭网页标签时浏览器崩溃。代码审查确认：`pagehide` 原先只保存索引，未统一释放音频、Worker、WebGL 场景；开发模块销毁后，旧动画循环没有取消。修订统一退出流程，取消帧回调和全局输入事件，终止解析、断开 Web Audio 和 Media Session、释放两个三维场景以及封面 URL。销毁播放器保留队列和进度。隐藏页面只暂停三维，后台音乐继续；进入往返缓存时暂停播放并保留可恢复场景。

新增自动测试覆盖：帧取消与重复销毁、往返缓存恢复、销毁保留队列/进度且不响应迟到媒体事件、关闭时正在解析播放资源、重复保存合并和 Worker 仅终止一次（合计 4 个新增测试用例）。

最终构建 `index-pPuI6jv-.js` / 离线版本 `63a634ae1fafc8ce`：内置 Chromium 中打开并载入 360° 查看器，再关闭标签、重新打开；浏览器继续正常工作，队列两项及暂停进度 0:05 保留。导航至本地许可页后返回也可继续渲染，无控制台错误。截图 `music-player-after-close.jpg`。

没有复现用户所用浏览器的原始崩溃，尚未获得该浏览器名称、版本或崩溃记录。这轮实际文件选择器自动化未成功，因此没有把“正在播放的 WAV 时关闭”标为本轮实测通过；音频退出和延迟载入通过受控替身测试验证。需要用户在更新后的实际浏览器上确认结果。
