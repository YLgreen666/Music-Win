# 音乐播放器：保持画质的性能优化

2026-10-09。本轮从 `music-player` 的 `0b8b6f9` 开始，仅修改网页实现，不部署、不推送上游。

## 保持的画面配置

没有修改 `render-quality.ts`、模型资产、封面裁切与尺寸、玻璃透明度、抽取高度、相机轨迹、波浪或归位规则。原始预设仍为渲染比例 100%、DPR 上限 1.5、抗锯齿关闭、2048 阴影、32 样本全分辨率 AO、景深 100%、透明材质分辨率 100%、纹理过滤 16。

图集仍为 2048×2048、8×8 格、256×256 每格；0 为占位图，63 个歌曲槽。保留 sRGB、线性过滤、mipmap 与各向异性设置。内部 CPU 像素按行翻转，使新的 DataTexture 与旧 CanvasTexture 使用同一 UV 和裁切。

## 实现

- 场景复用可见封面记录、容器、临时向量及波浪缓存；背景封面直接读取已有实例矩阵。矩阵和槽编号分别使用 `InstanceUpdates`，只标记变化区间；扩容释放旧实例缓冲。
- 图集按当前选中、归位中、距当前卡片最近的可见歌曲分配优先级。空余槽保留最近内容，超过容量只淘汰未受保护的缓存。图集容量不能容纳所有可见的唯一歌曲时，继续显示占位图。
- 最多两个取图/解码任务并发；已离开目标窗口的任务取消。结果由歌曲 ID、Blob/URL 版本、槽位代次及场景生命周期共同校验，旧结果关闭位图。完成结果在下一次场景更新集中绘制，每帧最多一次图集版本提交。
- 从首次绘制起将采样画布留在 CPU，复用主色采样画布，避免原图集的 GPU→CPU 读回。图集按脏格提交行更新；首次上传、上下文恢复或大量脏格使用整图。保持 mipmap。图集与标签在阴影/主绘制之前上传，避免在绘制通道中途插入上传。
- 完成转正和下降的模型、独立标签画布和材质进入最多八组的空闲池。仍在动画中的模型不受空闲池上限截断，快速重选沿用原运动状态。关闭时释放池与活动模型。
- 缓存材质引用，按原顺序应用外观、解密与封面覆盖；避免逐帧重建扫描角点、重复投影及无变化的 DOM 写入。
- 图集版本、槽编号、边框颜色与异步完成进入画面失效判断。原有阴影缓存、共享深度及静止帧复用继续工作。

## 可复现诊断

```powershell
npm run build:performance
npm run preview:performance
```

打开 `http://127.0.0.1:4183/verification/music-performance.html`。诊断页独立生成 1000 首合成歌曲及 30 个不同长度专辑，不读取 IndexedDB、个人文件或网易云登录，不请求平台 API。正常生产构建不包含诊断入口或 GPU 计时器。

同一窗口、1920×1080、DPR 1、原始画质、完整动态效果，每轮依次执行封面首次路线、封面重复路线、内构首次路线、内构重复路线，各 8 秒，重复三轮。每 160ms 选曲，先向前再反向，期间抽取、归位，末段使用固定模拟频段浏览。第二路线重复第一路线；63 槽容量有限，所以“重复”不表示所有封面都驻留。首次路线也不等于网络或模型首次启动耗时。

自动路线调用真实场景选曲入口，不能等同真实鼠标拖动。诊断页保留原输入事件，另提供主题、抽取、查看器、0/1/200/1000 首切换和实际 HTMLAudio 测试音频。

CPU 计时覆盖场景更新和绘制提交；选曲调用另以 `selectionCPU` 记录。帧间隔来自 requestAnimationFrame，包含异步工作及调度等待。GPU 使用 `EXT_disjoint_timer_query_webgl2` 异步查询，不调用 `finish` 或同步读像素；不支持时显示 null。图集上传数来自 texture.onUpdate，表示纹理提交次数，不是底层每次 texSubImage2D 调用数。`stagedBytes` 为 CPU 整理的脏格字节数，不含 GPU mipmap 或首次整图开销。

可选 `?uploads=1` 单独诊断上传调用耗时；该模式会改变上传时机，不用于正式前后对比。隐藏诊断标签会停止当前测量，防止后台限频混入记录。

## 本机验证范围

浏览器公开的实际 WebGL 设备为 `ANGLE (NVIDIA, NVIDIA GeForce RTX 5070 Ti Laptop GPU (0x00002F58) Direct3D11 vs_5_0 ps_5_0, D3D11)`。本机另有 Radeon 610M；不能从 `powerPreference: high-performance` 推断使用哪块显卡。本次实测通过 Codex 内置 Chromium 浏览器完成，不代表独立 Chrome/Edge 或手机认证。

- 38 项 `npm test` 通过，包含增量缓冲、700 实例扩容、千首索引、LRU 淘汰、两任务并发、过期 Blob/URL 解码丢弃、异步图集/槽版本触发重绘、翻转行与相邻格不污染、上下文恢复完整上传、池上限及一次性释放。保留已有播放、持久化与页面生命周期测试。
- `npm run typecheck`、生产构建与 PWA 资源打包通过。构建保留既有大 chunk 提示。
- 浏览器检查了零首、一首、200 首和 1000 首合成目录；自动三轮覆盖连续反向选曲及抽取归位。真实鼠标拖动/触摸惯性及独立 Chrome/Edge 尚需手动回归，未将程序化选曲记录当作拖动验收。
- 实际 HTMLAudio 测试音频在切换外观、抽取和打开/拆解/重组/返回查看器期间持续播放，同一歌曲进度从约 0.5s 推进至 21.8s。跳转离开诊断页后释放播放器。本次未使用个人音乐或网络歌曲进行播放测试。
- 封面模式图集第 8、16、32、63 槽与暖色封面检查无浏览器错误；保留 `flat` 槽编号与整数舍入，未撤回行边界采样修复。
- 固定姿态蓝色封面与原内构截图均为 1920×1080，见 `music-cover-before.jpg` / `music-cover-after.jpg`、`music-original-before.jpg` / `music-original-after.jpg`。用于检查封面尺寸、主色玻璃、阴影、景深和内构。模型区域 x=150–990、y=180–870 每 8 像素取样的 RGB 平均绝对差分别为 0.73、0.51（0–255 标度）；JPEG 压缩和时序仍存在差异，不声称逐像素相等。暖色回归画面见 `music-cover-warm-after.jpg`。
- 三轮后图集驻留保持 63，解码并发始终不超过 2；空闲池通常为 2，额外切换后到 8。纹理数稳定 33；内构首次编译后几何数稳定 20、程序数稳定 49。查看器关闭及目录切换后曾记录纹理数回落到 23。这些是 Three.js 资源计数，不是系统显存测量。

## 测量结果与限制

完整逐轮数据保存在 `music-performance-before.json`、`music-performance-before-recheck.json` 和 `music-performance-after.json`。基版在最终优化测量之后再次运行三轮，确认改善方向仍成立；下面优先使用这次追加基版复测。各段的 P50/P95 是该段分位数，汇总中使用三段分位数的中位数，不能当作合并所有帧重新计算的分位数。

| 外观 / 路线 | 基版复测 P50 / P95 (ms) | 优化 P50 / P95 (ms) | >50ms 帧数，三段合计：基版 / 优化 |
| --- | --- | --- | --- |
| 封面 / 首次 | 52.9 / 88.3 | 5.9 / 6.2 | 253 / 3 |
| 封面 / 重复 | 47.1 / 93.8 | 5.9 / 6.1 | 231 / 0 |
| 内构 / 首次 | 5.9 / 11.6 | 5.9 / 6.4 | 11 / 3 |
| 内构 / 重复 | 5.9 / 6.2 | 5.9 / 6.3 | 3 / 0 |

每组路线三段合计约 24 秒。基版封面首次总计 471 个帧间隔，优化 3861 个；重复路线基版 523 个、优化 3944 个。上传次数反而增加：基版各段约 136–171 次，优化约 305–351 次，这是更多帧及时完成局部提交，不表示上传字节量变大。最终封面 GPU P95 为 6.2–6.6ms，基版复测为 52.6–62.8ms；内构两者约 6.4–7.3ms。主要改善来自封面图集路径，不能宣称内构的平均帧率显著提高。

本机负载、显卡频率与窗口调度未被锁定；较早基版的内构 P95 达 70.6–129.4ms，而追加复测已回到 6.2–11.6ms，说明环境波动不可忽略，因此不把全部差额解释为代码的固定加速倍数。最终优化记录达到 60 FPS 所需的 16.7ms 帧预算；首次切换仍记录少量超过 50ms 的编译/载入停顿。其他显卡、实际图片解码和不同浏览器应重新测量；本轮没有用降画质掩盖剩余瓶颈。

完成后停止本轮创建的诊断服务，清理隔离基版与中间构建；保留复测命令、源码和证据，不恢复临时网站。
